2. DETALLE TECNICO DE LOS ENDPOINTS DEL BACKEND (WALLET API)
--------------------------------------------------------------------------------

A. GET /api/balance/:address
   - Proposito: Obtener el saldo consolidado de una direccion Korsh.
   - Validacion de Entrada: Regex ^[SR][1-9A-HJ-NP-Za-km-z]{25,34}$
   - Fuente de Datos: Explorer API (/ext/getbalance/:address y /ext/getaddress/:address).
   - Formato de Respuesta:
     {
       "balance": 91258138646,   // En duffs (1 KSH = 1e8 duffs)
       "received": 91258138646,  // Total historico recibido en duffs
       "sent": 0                 // Total historico enviado en duffs
     }
   - Evaluacion: Seguro y verificado con nodo real.

B. GET /api/utxos/:address
   - Proposito: Localizar las salidas no gastadas (UTXOs) necesarias para armar y
     firmar una nueva transaccion en el navegador del cliente.
   - Mecanismo:
     1. Consulta las ultimas transacciones asociadas a la direccion en el Explorer.
     2. Filtra transacciones con 'type: vout'.
     3. Invoca la llamada RPC 'getrawtransaction' y 'gettxout' para verificar
        si el output sigue sin gastar en el UTXO set del nodo.
   - Formato de Respuesta:
     [
       {
         "txid": "7d3a7d5c339b2dc54a79d28a4c13818e40b189cbe0609d03255fc8e68e3e355d",
         "vout": 0,
         "amount": 1.37200000,
         "scriptPubKey": "76a914...88ac"
       }
     ]
   - Evaluacion: Proceso no custodial. Las claves privadas nunca tocan el backend.

C. GET /api/history/:address
   - Proposito: Proveer la lista de movimientos (ingresos y egresos).
   - Fuente de Datos: Explorer /ext/getaddresstxs/:address/0/50.
   - Formato de Respuesta:
     [
       {
         "txid": "7d3a7d5c339b2dc5...",
         "sent": 1.372,
         "received": 0,
         "balance": 912.58138646,
         "timestamp": 1790309472
       }
     ]
   - OBSERVACION CRITICA RESUELTA:
     En la API de Iquidus Explorer, la propiedad 'sent' indica monedas enviadas
     HACIA la direccion (ingreso/abono), mientras que 'received' indica monedas
     transferidas DESDE la direccion (egreso/gasto). Se corrigio la interpretacion
     en el frontend para mostrar los estados e iconos correctos (+ Recibido en verde,
     - Enviado en rojo).

D. GET /api/rawtx/:txid
   - Proposito: Entrega el script hexadecimal original de la transaccion requerida
     por 'bitcoinjs-lib' / Psbt para calcular el 'nonWitnessUtxo' al firmar P2PKH.
   - Fuente: Llamada RPC 'getrawtransaction [txid, false]'.

E. POST /api/broadcast
   - Proposito: Transmitir a la red P2P una transaccion ya firmada por el usuario.
   - Entrada: { "hex": "0100000001..." } (Hexadecimal validado por regex).
   - Rate Limit Estricto: 5 solicitudes por minuto por IP para evitar spam o flooding.
   - Fuente: Llamada RPC 'sendrawtransaction [hex]'.
   - Retorno: { "txid": "64_caracteres_hex" }.

F. GET /api/info
   - Proposito: Metadatos de la cadena para validar conectividad con el nodo.
   - Fuente: Llamada RPC 'getblockchaininfo'.

3. AUDITORIA DE SEGURIDAD Y VULNERABILIDADES
--------------------------------------------------------------------------------

[OK] ARQUITECTURA NO-CUSTODIAL:
     El backend NO almacena contraseñas, semillas mnemónicas (12 palabras) ni
     claves privadas. La generación mnemónica (BIP39), derivación BIP32/BIP44
     (path m/44'/5001'/0'/0/0) y firmado de transacciones se realizan 100% de
     forma local en el navegador del cliente mediante Web Crypto API (PBKDF2 con
     600,000 iteraciones + AES-GCM 256-bit).

[OK] PROTECCION DE ENCABEZADOS Y CABECERAS HTTP:
     - Helmet.js activo implementando Content-Security-Policy, X-Frame-Options: DENY,
       X-Content-Type-Options: nosniff y HSTS.
     - Body parser limitado a 100kb para prevenir ataques de denegacion de servicio.

[OK] CONTROL DE RATELIMIT:
     - 60 peticiones/minuto por IP en endpoints generales (/api/*).
     - 5 peticiones/minuto por IP en endpoint de transmision (/api/broadcast).

[CORRECCION APLICADA] CORS ORIGIN:
     El valor por defecto original estaba estrictamente fijado a 'https://wallet.korsh.org'.
     Se ha flexibilizado para permitir desarrollo local (localhost:5173, localhost:3000,
     127.0.0.1) y despliegue multidominio/webapp de forma segura.

[CORRECCION APLICADA] FALLBACK DE EXPLORER URL:
     Originalmente apuntaba por defecto al puerto local 8091 ('http://127.0.0.1:8091').
     Se ha añadido fallback automático al nodo explorador oficial en vivo
     'https://explorer.korsh.org', garantizando que el frontend y backend operen
     sin requerir una instancia local pesada de MongoDB e Iquidus.
